# 세무 상담 보조 데스크톱 애플리케이션 기획서

> 가칭: **TaxBrief** (세무사 상담 중 즉석에서 법령 근거를 조회하고, 고객에게 전달할 PDF 요약 보고서를 자동 생성하는 1인용 데스크톱 도구)

---

## 1. 프로젝트 개요

### 1.1 한 줄 요약
세무사가 고객 상담 중 떠오르는 질문을 입력하면, **국가법령정보센터 공식 OPEN API**로 관련 법령·판례·해석례를 조회하고, **LLM이 정리한 근거 기반 요약 + 고객용 PDF 보고서**를 즉시 생성하는 1인 사용 데스크톱 애플리케이션.

### 1.2 해결하려는 문제
- 상담 중 고객 질문에 대해 *기억이나 감*에 의존해 답하면 정확성·신뢰성이 떨어짐.
- 법령 원문을 검색·교차확인하는 시간이 부족함 (상담은 실시간으로 흘러감).
- 상담 후 고객에게 정리된 자료를 따로 만들어 주려면 별도 시간이 필요함.

### 1.3 핵심 가치 제안
| 누구에게 | 무엇을 | 어떻게 |
|---|---|---|
| 상담 중인 세무사에게 | 자신감 있게 답할 수 있는 **근거 자료** | 30초 이내 법령 조회 + 요약 |
| 고객에게 | 상담 후 가져갈 수 있는 **공식문서급 자료** | PDF 형식의 출처 명시 보고서 |

## 2. 사용자 정의

### 2.1 타겟 사용자
- **1차 사용자**: 본인(세무사) — 단일 사용자
- **2차 수혜자**: 상담 받는 개인/법인 고객 (보고서를 받는 사람)

### 2.2 사용 환경
- 사무실 데스크톱(주) + 노트북(외부 상담)
- 인터넷 연결 환경 (법령 API 호출, LLM 호출 필요)
- 윈도우 / macOS 모두 지원 권장

### 2.3 대표 사용 시나리오
**시나리오 A — 상담 중 즉석 질의**
1. 고객: "1세대 1주택 비과세 받으려면 거주 요건이 어떻게 되나요?"
2. 세무사가 앱에 한 줄 입력: `1세대 1주택 비과세 거주요건`
3. 5~15초 안에 화면에 요약·조문·핵심 포인트 표시
4. 세무사가 그 내용을 보며 고객에게 자연스럽게 설명
5. 상담 종료 시 "PDF 생성" 버튼 → 고객 이메일/USB로 전달

**시나리오 B — 사후 정리**
1. 상담 종료 후 그날 했던 질의 5건의 보고서를 일괄 PDF 묶음으로 출력해 보관

## 3. 핵심 기능 (Functional Requirements)

### 3.1 MVP 범위 (반드시 포함)

| ID | 기능 | 설명 |
|---|---|---|
| F-01 | 자연어 질문 입력 | 단일 입력창 (멀티라인 지원). 단축키 `Ctrl/Cmd+Enter`로 실행. |
| F-02 | 법령 자동 조회 | 국가법령정보센터 OPEN API로 관련 법령·조문 검색 |
| F-03 | LLM 기반 답변 생성 | 조회된 법령 원문을 컨텍스트로 사용해 **근거 인용된** 답변 작성 |
| F-04 | 출처 표시 | 답변의 각 문단에 출처(법령명·조항·항·호) 인라인 표기 |
| F-05 | 상담 세션 관리 | 한 명의 고객 = 하나의 세션. 세션 내 여러 질의 누적 |
| F-06 | PDF 보고서 생성 | 세션 전체 또는 개별 질의에 대해 고객용 PDF 출력 |
| F-07 | 로컬 이력 저장 | 모든 질의·응답·생성된 PDF 로컬 DB에 저장. 추후 재검색 가능 |
| F-08 | 답변 편집 | LLM 답변을 세무사가 직접 수정한 뒤 PDF 출력 가능 |

### 3.2 2차 범위 (MVP 이후)

| ID | 기능 | 설명 |
|---|---|---|
| F-09 | 판례·해석례 추가 조회 | 법령뿐 아니라 판례·국세청 해석례·조세심판원 결정례 검색 |
| F-10 | 즐겨찾기·태그 | 자주 묻는 질의를 태깅·그룹화 |
| F-11 | 보고서 템플릿 | 회사 로고·면책조항 등 커스터마이즈 |
| F-12 | 고객 정보 관리 | 고객 기본정보(이름·연락처·사업자번호)와 세션 연결 |
| F-13 | 이메일 직접 발송 | PDF 생성 후 고객 메일로 바로 발송 |
| F-14 | 오프라인 캐시 | 자주 보는 법령 원문 로컬 캐시 |

### 3.3 명시적으로 제외 (Out of Scope, MVP)
- 다중 사용자/권한 관리
- 결제·구독 시스템
- 모바일 앱
- 자동 세금 계산기 (이번 앱은 **상담 보조 + 근거 제시**가 핵심, 계산기 아님)
- 법률 자문 자동화 (이 앱은 어디까지나 **세무사 본인의 판단**을 보조)

## 4. 비기능 요구사항 (Non-Functional Requirements)

| 항목 | 기준 |
|---|---|
| **응답 시간** | 일반 질의 응답 표시까지 ≤ 20초 (법령 조회 + LLM 응답 포함) |
| **정확성** | 모든 LLM 답변은 반드시 **인용 원문**과 함께 제공. 인용 없는 단정 금지 |
| **신뢰성** | 외부 API 실패 시 명확한 에러 표시 (조용한 실패 금지) |
| **오프라인** | 로컬 이력 조회는 오프라인에서도 가능. 신규 질의는 온라인 필요 |
| **보안** | API 키는 OS 키체인 저장. 고객 정보는 로컬 DB(암호화) |
| **개인정보** | 고객의 개인정보(이름·주민번호 등)는 LLM에 전달하지 않음 (또는 마스킹) |
| **호환성** | Windows 10+, macOS 12+ |
| **로깅** | 모든 API 호출/응답을 로컬에 기록 (추후 감사·디버깅용) |

## 5. 시스템 아키텍처

### 5.1 전체 구조

```
┌─────────────────────────────────────────────────┐
│              데스크톱 앱 (Electron)              │
│  ┌───────────────┐    ┌──────────────────────┐  │
│  │   Renderer    │    │     Main Process     │  │
│  │ (React + TS)  │◀──▶│  (Node.js / Electron)│  │
│  │   - 입력 UI   │    │   - API 오케스트레이션 │  │
│  │   - 결과 뷰    │    │   - PDF 생성          │  │
│  │   - PDF 미리보기│    │   - DB I/O           │  │
│  └───────────────┘    └──────────┬───────────┘  │
│                                  │              │
│                       ┌──────────▼──────────┐   │
│                       │   로컬 SQLite DB    │   │
│                       │ (세션·질의·이력)     │   │
│                       └─────────────────────┘   │
└──────────────────────┬──────────────────────────┘
                       │ HTTPS
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ 국가법령정보  │ │ Claude API   │ │  (선택)      │
│ 센터 OPEN API│ │ (LLM)        │ │ 국세청 API   │
└──────────────┘ └──────────────┘ └──────────────┘
```

### 5.2 처리 흐름 (질의 1건 기준)

```
사용자 입력
   │
   ▼
[1] 질의 정규화 (LLM)
    - 사용자 자연어 → 법령 검색 키워드 추출
    - 예: "1세대 1주택 비과세 거주요건"
         → ["소득세법", "1세대 1주택", "비과세", "거주요건"]
   │
   ▼
[2] 법령 검색 (국가법령정보센터 API)
    - 키워드별 검색 → 후보 법령 N개
    - 관련 조문 본문 fetch
   │
   ▼
[3] 컨텍스트 구성
    - 검색된 법령 원문을 LLM 프롬프트에 첨부
    - 프롬프트 캐싱 활용 (자주 쓰는 시스템 프롬프트)
   │
   ▼
[4] LLM 응답 생성 (Claude API)
    - 출력 형식: 요약 / 상세 / 인용 / 면책
    - 반드시 인용 원문과 매칭
   │
   ▼
[5] 화면 표시 + DB 저장
    - 세무사가 검토 → (필요 시) 편집
   │
   ▼
[6] PDF 생성 (요청 시)
    - HTML 템플릿 + Puppeteer or react-pdf
    - 출처 페이지 자동 첨부
```

## 6. 기술 스택 제안

| 영역 | 선택 | 이유 |
|---|---|---|
| **데스크톱 셸** | Electron | 한글 폰트/PDF/Node 생태계 호환성이 가장 검증됨. 1인 도구라 번들 크기는 비치명적 |
| **UI** | React + TypeScript + Tailwind | 빠른 화면 구성, 타입 안전성 |
| **상태 관리** | Zustand 또는 React Query | 가볍고 학습 곡선 낮음 |
| **로컬 DB** | SQLite (better-sqlite3) | 단일 사용자 환경에 충분. 백업·이동 용이 |
| **LLM** | Claude API (Sonnet 4.6 또는 Opus 4.7) | 한국어 법률 텍스트 처리 품질 + 프롬프트 캐싱 |
| **법령 API** | 국가법령정보센터 OPEN API | 공식·무료·신뢰 가능 |
| **PDF 생성** | Puppeteer (Chromium 헤드리스) | HTML/CSS 그대로 렌더 → 한글·표 깨끗하게 출력 |
| **빌드** | electron-vite + electron-builder | 표준 조합 |
| **키 저장** | keytar (OS 키체인) | API 키 안전 보관 |
| **로깅** | electron-log | 파일 기반 로깅 |

> **대안 검토**: Tauri(Rust)도 좋지만, ① 한글 PDF 생성 시 폰트/표 처리 검증이 더 까다롭고, ② 1인 사용이라 번들 크기 차이는 의미 없음 → Electron 권장.

## 7. 외부 연동: 국가법령정보센터 OPEN API

### 7.1 사전 준비
1. https://open.law.go.kr 접속 → 회원가입
2. **인증키(OC)** 발급 신청 (보통 1~3 영업일)
3. 이메일 형식의 OC ID 수령 → 앱 설정에 입력

### 7.2 주요 사용 엔드포인트 (예상)
| 용도 | 엔드포인트 |
|---|---|
| 법령 검색 | `lawSearch.do?OC={OC}&target=law&query={키워드}&type=JSON` |
| 법령 본문 | `lawService.do?OC={OC}&target=law&MST={마스터번호}&type=JSON` |
| 조문 단위 조회 | `lawService.do?...&JO={조번호}` |
| 행정해석례 | `target=expc` |
| 판례 | `target=prec` |

> 실제 파라미터·응답 스키마는 발급 후 제공되는 API 가이드 문서에 맞춰 확정.

### 7.3 호출 정책
- 키워드 1건당 검색 호출 1회 → 상위 5건 본문 호출 (병렬)
- 응답은 24시간 로컬 캐시 (같은 키워드 재검색 시 비용 절감)
- 호출 실패 시 3회까지 지수 백오프 재시도

## 8. LLM 사용 설계

### 8.1 사용 모델
- 기본: **Claude Sonnet 4.6** (비용·품질 균형)
- 복잡 질의/고객 사안용: **Claude Opus 4.7** 옵션 토글
- 모델 ID 예: `claude-sonnet-4-6`, `claude-opus-4-7`

### 8.2 프롬프트 구조
```
[System 프롬프트 - 캐시 대상]
- 너는 한국 세무 상담을 보조하는 어시스턴트다.
- 모든 답변은 제공된 법령 원문에 근거해야 한다.
- 원문에 없는 내용은 "원문에서 확인 불가"라고 명시한다.
- 출력 형식: (1) 한 줄 요약 (2) 상세 설명 (3) 인용 조문 (4) 면책 문구

[User 프롬프트]
- 세무사 질문: "{질문}"
- 관련 법령 원문:
  ---
  {법령1 원문}
  ---
  {법령2 원문}
  ---
```

### 8.3 프롬프트 캐싱
- 시스템 프롬프트 + 자주 쓰는 법령 원문(소득세법 등 주요 세법)을 **캐시 영역**에 두어 비용·지연 최소화

### 8.4 환각 방지 장치
- 응답은 항상 JSON 스키마로 강제 (`citation` 필드 필수)
- `citation`이 비어 있으면 화면에 "⚠️ 근거 부족" 경고 표시

## 9. 데이터 모델 (SQLite)

```sql
-- 상담 세션 (보통 고객 1명 = 세션 1개)
CREATE TABLE session (
  id          TEXT PRIMARY KEY,         -- ULID
  client_name TEXT,                     -- 고객 식별용 (옵션)
  client_memo TEXT,
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  closed_at   DATETIME
);

-- 개별 질의·응답
CREATE TABLE query (
  id            TEXT PRIMARY KEY,
  session_id    TEXT NOT NULL REFERENCES session(id),
  question      TEXT NOT NULL,
  answer_md     TEXT NOT NULL,          -- LLM 응답 (마크다운)
  answer_edited TEXT,                   -- 세무사가 수정한 버전
  model         TEXT,                   -- 사용된 모델 ID
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 인용 출처
CREATE TABLE citation (
  id         TEXT PRIMARY KEY,
  query_id   TEXT NOT NULL REFERENCES query(id),
  law_name   TEXT,                      -- 예: 소득세법
  article    TEXT,                      -- 예: 제89조
  paragraph  TEXT,                      -- 예: 제1항 제3호
  excerpt    TEXT,                      -- 원문 발췌
  source_url TEXT
);

-- 생성된 PDF
CREATE TABLE report (
  id         TEXT PRIMARY KEY,
  session_id TEXT REFERENCES session(id),
  query_id   TEXT REFERENCES query(id), -- NULL이면 세션 전체 보고서
  file_path  TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 법령 본문 캐시
CREATE TABLE law_cache (
  key        TEXT PRIMARY KEY,          -- 예: "law:001234:JO_089"
  body       TEXT NOT NULL,
  fetched_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 10. 화면 구성 (UI Flow)

### 10.1 화면 목록
1. **메인 (상담 화면)** — 좌측 세션 목록 / 우측 질의·응답 스레드
2. **질의 입력 패널** — 하단 고정. Ctrl+Enter로 전송
3. **응답 카드** — 요약·상세·인용·편집 토글
4. **PDF 미리보기 모달** — 출력 전 확인 + 저장/공유
5. **설정** — API 키 (법령 OC, Claude API Key), 모델 선택, 보고서 템플릿
6. **이력 검색** — 과거 세션·질의 전문 검색

### 10.2 메인 화면 와이어프레임 (개념)

```
┌────────────────────────────────────────────────────────┐

├──────────────┬─────────────────────────────────────────┤

│ 세션 목록     │ ─────────────────────────────────────── │
│              │  Q. 1세대 1주택 비과세 거주요건은?       │
│ ▸ 김OO       │  ┌─────────────────────────────────┐    │
│   2026-05-22 │  │ 요약: 조정대상지역은 2년 거주... │    │
```

## 12. 보안 / 개인정보 / 컴플라이언스

| 항목 | 정책 |
|---|---|
| API 키 보관 | OS 키체인(keytar). 평문 파일 저장 금지 |
| 로컬 DB | SQLCipher로 암호화 (선택), 사용자 비밀번호 1개로 잠금 |
| 고객 개인정보 | 이름·연락처는 로컬 DB만. **LLM 호출 시 마스킹** |
| 법령 출처 표기 | 모든 인용에 출처·조문번호·URL 필수 |
| 면책 문구 | 모든 PDF 하단에 "일반 안내·최종 판단은 세무사 협의" 명시 |
| 데이터 백업 | 사용자가 수동으로 DB 파일 내보내기/가져오기 가능 |
| 감사 로그 | 모든 LLM·API 호출 로컬 파일에 기록 (날짜별 회전) |

## 13. 개발 단계 (Phases)

### Phase 0 — 사전 준비 (1주)
- 국가법령정보센터 OC 발급 신청
- Claude API 키 발급 / 결제수단 등록
- API 가이드 문서 정독, 응답 스키마 파악
- 디자인 시안 (Figma 또는 손그림 와이어프레임)

### Phase 1 — MVP 핵심 흐름 (2~3주)
- Electron + React + Tailwind 보일러플레이트
- SQLite 스키마 마이그레이션
- 법령 검색 API 클라이언트 (검색 → 본문 fetch → 캐시)
- Claude API 클라이언트 + 프롬프트 캐싱
- 단일 질의→응답 흐름 (출처 인라인 표시)
- 기본 PDF 출력 (Puppeteer)

### Phase 2 — 사용성 (1~2주)
- 세션 관리 (좌측 목록)
- 응답 편집 UI
- 보고서 템플릿(로고/면책) 커스터마이즈
- 이력 검색

### Phase 3 — 안정화 (1주)
- 에러 처리·재시도 정책
- 로깅·감사
- 빌드·서명·자동 업데이트 (electron-updater)
- 실제 상담 1주일 베타 사용 → 피드백 수집

### Phase 4 — 확장 (이후)
- 판례·해석례 추가
- 이메일 발송
- 고객 정보 정식 관리

> **총 소요 예상**: 사전 준비 제외 약 **5~7주**. 본인이 직접 개발 시 가용 시간에 따라 조정.

## 14. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 법령 API 응답 지연·다운 | 상담 중 답변 못함 | 캐시 활용 + 다운 시 "수기 조회" 모드 안내 |
| LLM 환각(없는 조항 인용) | 신뢰도 치명적 | 인용 원문 자동 매칭 검증 + 매칭 실패 시 경고 |
| 법령 개정 누락 | 잘못된 안내 | 답변 상단에 "조회 시점: YYYY-MM-DD" 명시, 시행일 정보 표기 |
| API 사용 비용 증가 | 운영 부담 | 프롬프트 캐싱, 모델 선택 토글, 월별 비용 대시보드 |
| 고객 개인정보 유출 | 법적·신뢰 | 마스킹 + 키체인 + 로그 회전 |
| PDF 한글 깨짐 | 보고서 품질 | 사전에 Noto Sans KR 번들, 표·줄바꿈 테스트 케이스 마련 |
| **법적 책임 한계** | 사용자 보호 | PDF·UI에 "본 자료는 일반 안내" 면책 의무 표기 |
