# 세무 상담 보조 도구 — MVP 기획서 (Today 버전)

> 가칭: **TaxBrief**
> 목표: **오늘 안에 본인이 직접 한 건 이상 실사용**해 보는 것.
> 본 문서는 "오늘 사용"이라는 단일 제약에 맞춰 의도적으로 좁힌 최소 스펙이다.
> 폐기된 기능은 [§9 Phase 2 보류 목록]에 보존.

---

## 1. MVP 정의 (한 문장)

> 로컬에서 `npm run dev` 로 실행되는 단일 페이지 웹앱. 질문 한 줄을 입력하면 국가법령정보센터에서 관련 법령을 조회·요약하여 화면에 보여주고, **브라우저 인쇄(Cmd/Ctrl+P)** 로 PDF 저장할 수 있다.

이게 전부다. 그 외 모든 것은 오늘 만들지 않는다.

---

## 2. 오늘 작동해야 하는 최소 흐름 (Happy Path)

```
[1] 사용자가 브라우저에서 localhost 접속
[2] 입력창에 한국어 질문 입력 (예: "1세대 1주택 비과세 거주요건")
[3] [상담 보고서 생성] 버튼 클릭
[4] 서버가:
     ① Claude로 검색 키워드 추출
     ② 국가법령정보센터 OPEN API 호출 (법령 검색 + 상위 N건 본문 조회)
     ③ Claude로 근거 인용 답변 생성
[5] 화면에 결과 표시: 질문 / 요약 / 상세 / 인용 조문 / 면책
[6] 사용자가 Ctrl+P → "PDF로 저장" 선택 → 끝
```

이 흐름이 처음부터 끝까지 막힘없이 도는 것 = 오늘의 성공 기준.

---

## 3. 기술 스택 (최소)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Next.js 15 (App Router)** | API Route 내장 → API 키 노출 없이 호출 |
| 언어 | TypeScript | 타입 안전, AI 도구 친화 |
| 스타일 | TailwindCSS | 빠른 스타일링, 인쇄 CSS 분리 용이 |
| LLM | `@anthropic-ai/sdk` (`claude-sonnet-4-6`) | 한국어 품질·속도 균형 |
| 법령 API | native `fetch` | 별도 SDK 없음 |
| **PDF 생성** | **브라우저 인쇄(Ctrl+P → PDF로 저장)** | 라이브러리 0개. 인쇄용 CSS만 작성 |
| DB | **없음** | 오늘은 저장 안 함 |
| 인증 | **없음** | 로컬 단독 실행 |
| 배포 | **없음** | `npm run dev` 로컬만 |

**의도**: 의존성·빌드 단계를 줄여, "코드 → 실행 → 사용"까지의 거리를 짧게.

---

## 4. 이번 MVP에 **포함되지 않는** 것 (의도적 제외)

다음은 모두 가치 있지만 **오늘 만들지 않는다**.

- ❌ Electron 데스크톱 빌드 / 아이콘 / 코드사이닝
- ❌ SQLite·이력 저장·재검색
- ❌ 세션 / 고객 정보 / 다중 상담 관리
- ❌ 답변 편집 UI
- ❌ 설정 화면 (모든 키는 `.env.local`로 처리)
- ❌ 회사 로고·보고서 템플릿 커스터마이즈 (단일 기본 템플릿만)
- ❌ 판례·해석례 조회 (법령만)
- ❌ 캐싱·재시도 정책 정교화 (단순 try/catch만)
- ❌ 이메일 발송
- ❌ 로깅 인프라 (콘솔 출력으로 충분)
- ❌ 마스킹·암호화

> 이 목록의 의미: 위 항목들을 "안 만들어서 미완성"이 아니라, "안 만드는 게 오늘 MVP의 정답"이다.

## 8. API 계약

### 8.1 클라이언트 → 서버
```
POST /api/ask
Content-Type: application/json

{ "question": "1세대 1주택 비과세 거주요건은?" }
```

### 8.2 서버 응답
```ts
{
  question: string;
  summary: string;           // 3~5줄
  detail: string;            // 본문 (마크다운 허용)
  citations: Array<{
    lawName: string;         // 예: 소득세법
    article: string;         // 예: 제89조 제1항 제3호
    excerpt: string;         // 원문 발췌
    sourceUrl?: string;
  }>;
  disclaimer: string;        // 고정 면책 문구
  generatedAt: string;       // ISO datetime
  model: string;             // 사용된 모델 ID
}
```

### 8.3 서버 내부 처리 단계
1. 질문 → Claude → `{ keywords: string[] }` JSON 강제 출력
2. 키워드 → 국가법령정보센터 `lawSearch.do` → 상위 3건 ID 추출
3. 각 ID → `lawService.do` 본문 조회 (병렬, 3건이라 짧음)
4. (질문 + 법령 본문) → Claude → 위 응답 스키마 강제 출력
5. 클라이언트 반환

### 8.4 에러 처리 (최소)
- 법령 API 실패: 사용자에게 "법령 조회 실패. 잠시 후 재시도" 표시
- LLM 실패: 동일
- 재시도·캐시 없음 (오늘은 사용자가 다시 누르면 됨)

## 9. 작업 체크리스트 (오늘 실행)

각 항목은 30분~1시간 단위로 쪼개져 있음. **순서대로** 진행.

- [ ] **0. 키 준비**
  - [ ] `.env.local`에 `LAW_OC`, `ANTHROPIC_API_KEY` 입력
  - [ ] `LAW_OC` 발급처 사이트에서 키 활성 상태 확인 (호출 1회 테스트)
- [ ] **1. 프로젝트 부트스트랩**
  - [ ] `npx create-next-app@latest now --typescript --tailwind --app --no-src-dir`
  - [ ] `.gitignore` 확인 (`.env.local` 포함)
  - [ ] `npm i @anthropic-ai/sdk`
- [ ] **2. 법령 API 클라이언트 (`lib/law.ts`)**
  - [ ] `searchLaws(keyword)` — 검색 → ID 목록
  - [ ] `getLawBody(id)` — 본문 fetch
  - [ ] Node에서 단독 호출 테스트 (`tsx` 또는 임시 script로 1회 검증)
- [ ] **3. Claude 클라이언트 (`lib/claude.ts`)**
  - [ ] `extractKeywords(question)` — JSON 출력 강제
  - [ ] `synthesizeAnswer(question, lawBodies)` — 응답 스키마 강제
- [ ] **4. API Route (`app/api/ask/route.ts`)**
  - [ ] POST 핸들러: 위 두 모듈 오케스트레이션
  - [ ] curl로 호출 검증
- [ ] **5. UI (`app/page.tsx`)**
  - [ ] textarea + 버튼 + 결과 영역
  - [ ] 로딩 상태 (스피너 또는 "생성 중…")
  - [ ] 결과 렌더 (요약/상세/인용/면책)
- [ ] **6. 인쇄 CSS (`app/globals.css`)**
  - [ ] `@media print` 블록
  - [ ] 입력·버튼 숨김, 결과만 표시
  - [ ] 헤더(앱명·생성일자) 인쇄 시 표시
- [ ] **7. 실사용 1건**
  - [ ] 실제 본인이 떠올린 질문 1개로 끝까지 흐름 실행
  - [ ] PDF 저장 확인
  - [ ] 인용 조문 1개라도 실제 법령과 일치하는지 본인 검수

**오늘 완료 = 7번까지 통과.**

## 10. 위험과 대응 (오늘 한정)

| 위험 | 영향 | 오늘 대응 |
|---|---|---|
| 국가법령정보센터 API 응답 형식이 예상과 다름 | 흐름 멈춤 | 응답 raw를 그대로 LLM에 넣어도 됨. 파싱 과도 최적화 금지 |
| LLM이 없는 조항을 인용 | 신뢰 훼손 | 시스템 프롬프트에 "제공된 본문에 없는 조항은 인용 금지" 명시 + `excerpt` 빈 인용 자동 필터 |
| 한글 폰트 인쇄 깨짐 | PDF 품질 | `font-family: system-ui` 정도면 보통 OK. 안 되면 Google Fonts Noto Sans KR 1줄 추가 |
| 처음 응답 지연 | 사용 흐름 답답 | "최대 20초 소요" 안내 텍스트 + 진행 표시 |
| `.env.local` 누락으로 키 미로딩 | 500 에러 | 서버 시작 시 키 누락이면 즉시 throw + 친절한 콘솔 메시지 |

> 오늘 발생하지 않을 위험은 오늘 대응하지 않는다.

## 12. Phase 2 보류 목록 (오늘은 안 함, 잊지는 않음)

오늘 MVP가 1건이라도 실사용되면, 다음 우선순위로 확장:

1. **이력 저장** — SQLite + 질의 검색 (실사용 데이터가 쌓이기 시작하면 가장 먼저 필요)
2. **답변 편집 UI** — LLM 답변을 세무사가 수정 후 PDF 출력
3. **고객 정보 / 세션** — 누구에게 발행된 보고서인지 식별
4. **회사 로고·면책 커스터마이즈**
5. **판례·해석례 검색** 추가
6. **응답 캐싱** (같은 키워드 24h 재사용)
7. **Electron 패키징** — 본인 PC에 "앱 아이콘"으로 설치
8. **이메일 발송**

> 위 순서는 "실사용 시 가장 자주 아쉬울 가능성"을 기준으로 잠정 정렬. 실제 우선순위는 오늘 사용 후 본인 피드백으로 재조정.

- [ ] 실제 질문 1개를 처음부터 끝까지 흐름에 태웠다

5개 모두 ✓ = **오늘 MVP 성공**.
